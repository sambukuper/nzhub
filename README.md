# NZHub

VPN-клиент для Android на ядре Xray. Это пересобранный Happ 4.9.0: своё имя, свои
иконки, свои обновления, двенадцать тем вместо двух, ноль аналитики.

Идентификатор пакета `com.nzboost.nzhub`, поэтому форк встаёт рядом с оригинальным
Happ и не конфликтует с ним.

## Установка

Скачай APK из раздела Releases и поставь его обычным способом. Если под ним уже был
Happ с конфигами, сначала экспортируй их: у разных пакетов разные хранилища.

Проверить целостность файла:

```bash
sha256sum -c NZHub-1.0.0.apk.sha256
```

## Темы

Выбор в настройках, в разделе интерфейса. Применяется сразу, без перезапуска. Все
палитры проверены на контраст по WCAG AA.

Светлые: Light, Sunset, Rose, Lavender, High Contrast.
Тёмные: Dark, AMOLED Black, Midnight Blue, Forest, Ocean, Mono, Cyberpunk.
Плюс System: следует за системным день/ночь и за исходной настройкой Happ.

Цвета не зашиты в разметке. Всё идёт через токены темы (`colorBgMain`, `colorAccent`,
`colorText` и остальные), темы описаны одним файлом
`apktool/res/values/nzhub_themes.xml`. Своя тема это ещё один `<style>` плюс id в
`public.xml`.

## Обновления

Проверка ходит на GitHub Releases этого репозитория
(`api.github.com/repos/sambukuper/nzhub/releases/latest`), дальше сравнение версий по
числам из `tag_name` с установленной версией.

- При запуске, не чаще одного запроса в 6 часов, молча, если обновления нет.
- Кнопка «Проверить обновления» в настройках: там же чинлодж из текста релиза и
  установка прямо из приложения.
- Нет сети, поймал rate limit или релизов ещё нет: сообщаем и не падаем.

Приложение читает и `release` из корня этого репозитория. Это старый формат
конфигурации Happ, с принудительными обновлениями на случай, когда релиз нужно
выкатить срочно. Пути ведут на `sambukuper/nzhub`, официальные серверы Happ вырезаны.

## Что удалено

- Sentry: инициализация убрана из `HappApplication`, провайдеры убраны из манифеста.
- Firebase: провайдеры, приёмники и push-сервисы убраны из манифеста, а обращение к
  FCM в `MainViewModel` заменено на пропуск: без инициализации Firebase этот вызов
  упал бы с `IllegalStateException`.
- Ссылки на happ.su и happ-proxy.com в интерфейсе ведут на этот репозиторий.

Логи Xray и локальные уведомления остались, наружу они не ходят.

## Структура

```
apktool/                 проект Apktool: smali, res, манифест, нативные библиотеки
tools/ci_build.sh        сборка: apktool b, classes4.dex, zipalign, подпись
tools/inject/src/        наш Java-код (темы и обновления), едет в classes4.dex
tools/scripts/           генераторы иконок и тем, скрипты ребрендинга
release                  JSON конфигурации обновлений для старого механизма
app_domain/list.json     домены прямого подключения для подписок
CHANGELOG.md             текст релиза
```

## Сборка

Нужны JDK 17+, Python 3 и Android build-tools с `zipalign` и `apksigner`. На Linux
раннерах GitHub Actions build-tools лежат в образе; на Windows положи их в `tools/bt`
или возьми из `ANDROID_HOME`.

```bash
KEYSTORE=~/nzhub.keystore KEYSTORE_PASSWORD=... bash tools/ci_build.sh out/NZHub.apk
```

Без ключа скрипт соберёт одноразовый и предупредит: такой APK не обновит предыдущую
сборку.

`apktool/` собирается минут за пять. `classes4.dex` подкладывается в готовый архив
отдельным шагом: нативные библиотеки ссылаются на имена классов вида
`su/happ/tunnel/TProxyService`, и переименование пакетов их бы сломало. Свои классы
кладём рядом, чужие не переписываем.

## CI

`.github/workflows/build-apk.yml` собирает APK на каждый тег `v*` и на ручной запуск.
Релиз создаётся сам, с двумя именами одного файла: `NZHub-<версия>.apk` и стабильный
`NZHub-latest.apk`, на который ссылается `release`.

Секреты репозитория:

- `NZHUB_KEYSTORE_B64` с base64 подписывающего ключа
- `NZHUB_KEYSTORE_PASSWORD` с паролем к нему

```bash
base64 -w0 nzhub.keystore | gh secret set NZHUB_KEYSTORE_B64 -R sambukuper/nzhub
gh secret set NZHUB_KEYSTORE_PASSWORD -R sambukuper/nzhub
```

Новый релиз:

```bash
git tag v1.0.1 && git push origin v1.0.1
```

## Подпись

Один и тот же ключ для всех релизов, иначе обновление не встанет поверх установленного.
Ключ в репозиторий не попадает. Потеряешь ключ, потеряешь возможность обновлять уже
установленные копии: их придётся удалять.

## Ограничения

Это декомпилированный APK, а не исходники на Kotlin: правки идут на уровне smali и
ресурсов, поэтому дизайн упирается в то, что выражается в XML. Сборка проверена
статически (подпись, выравнивание, отсутствие несуществующих вызовов в `classes4.dex`),
на живом устройстве её ещё не гоняли.
